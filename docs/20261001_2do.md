# Repository baseline review — 2026-10-01

The baseline review was completed before feature development. No repository files were modified during the review. The pre-existing untracked `AGENTS.md` was left untouched. This document records the findings; it does not imply that any findings have been fixed.

The default checks pass, but confirmed defects affect date calculations, location isolation, stored settings, and release safety. These deserve attention before feature development.

Finding classifications:

- **Confirmed defect:** demonstrated by execution or directly established from the implementation.
- **Probable problem:** supported by the implementation, but not fully reproduced in the deployed application.
- **Maintainability concern:** increases complexity, inconsistency, or regression risk.
- **Optional improvement:** useful hardening or clarification without a demonstrated defect.

File line numbers refer to the reviewed baseline and may move after changes.

## ERROR

1. **Confirmed defect — overlapping requests can corrupt another location’s calculations.**
   `PlotUpdater.run()` starts with one location, awaits weather data, then writes through the mutable `this.locationId`. Switching tabs changes that ID while the request is pending. An in-memory reproduction confirmed that a request started for location A writes its results into location B. Older requests can also overwrite newer charts.
   References: [plotUpdater.js](../assets/js/plotUpdater.js), lines 90, 107, and 183; [main.js](../assets/js/main.js), line 1694.

   **FIXED — 2026-10-01.** Shared mutable location, cache, and intermediate calculation state survived asynchronous waits. Each run now has an isolated execution with captured location ownership and frozen view settings. Display generation checks suppress stale charts, labels, hints, and errors; separate per-location generation checks retain valid inactive-location calculations while preventing older runs for the same location from replacing newer calculations. Opening the comparison tab also invalidates pending location display updates. Leap-year/day-index behavior is unchanged.

   Regression coverage: [plotUpdaterConcurrency.test.js](../tests/plotUpdaterConcurrency.test.js) contains nine deferred-promise tests covering location ownership across an await, out-of-order completion with both locations stored, normal storage/display, same-location overlap, late multi-year responses, stale failures, weather fallback cache ownership, late location names, and display invalidation on leaving a location view. Before the fix, five initial race tests failed while the normal-run test passed. After the fix, all nine regression tests and the full Jest suite (18 suites, 75 tests) pass; `npm run lint` passes.

2. **Confirmed defect — GTS calculations depend incorrectly on the browser time zone.**
   Date-only strings are parsed as UTC, then interpreted using local calendar methods. In Los Angeles, January 1 becomes December 31 and receives the wrong monthly weight. Running the existing suite with `TZ=America/Los_Angeles` produced **four failures across two suites**.
   References: [logic.js](../assets/js/logic.js), lines 97 and 180; [utils.js](../assets/js/utils.js), line 28.

   **FIXED — 2026-10-01.** Date-only API and calculation values are now parsed and validated as local calendar dates through the shared `parseDateStringLocal()` helper. GTS weighting, filtering, comparison data, chart labels, and historical-to-recent range transitions no longer reinterpret `YYYY-MM-DD` values as UTC instants.

   Regression coverage: [timezoneDateHandling.test.js](../tests/timezoneDateHandling.test.js) starts a Node process with `TZ=America/Los_Angeles` and verifies January/February/March GTS weights, unchanged calendar labels, and inclusive full-year boundaries. The test failed before the fix. After the fix, the complete suite passes both normally and with `TZ=America/Los_Angeles` (19 suites, 76 tests); `npm run lint` passes.

3. **Confirmed defect — vegetation comparisons use incorrect crossing dates.**
   The comparison searches the displayed window and loads the full year only if no match exists. If the threshold was crossed before that window, it incorrectly uses the window’s first day. Separately, the day-of-year helper divides local elapsed milliseconds by 24 hours: March 30, 2026 in Berlin returns day **88 instead of 89**.
   References: [plotUpdater.js](../assets/js/plotUpdater.js), lines 688, 705, and 998.

   **FIXED — 2026-10-01.** A match at the first point of a displayed window now triggers a full-year lookup so the actual threshold crossing can be found. Crossings found later inside the displayed window continue to use that data. Day-of-year values now use UTC calendar components, avoiding daylight-saving offsets while retaining the additional day in leap years.

   Regression coverage: [plotUpdaterComparison.test.js](../tests/plotUpdaterComparison.test.js) verifies a threshold crossed before the display window, a crossing inside the window, day-of-year behavior across a daylight-saving transition, and leap-year indices. Both defect tests failed before the fix. After the fix, the full suite passes normally and with `TZ=America/Los_Angeles` (20 suites, 80 tests); `npm run lint` passes.

4. **Confirmed defect — moving a location retains calculations for its old coordinates.**
   Coordinate updates do not invalidate derived curves. Their cache keys contain date, timeframe, and year range, but no coordinates. A reproduction retrieved the old curves after changing coordinates.
   References: [main.js](../assets/js/main.js), line 2319; [ui.js](../assets/js/ui.js), line 193; [plotUpdater.js](../assets/js/plotUpdater.js), lines 934 and 1111.

   **FIXED — 2026-10-01.** `updateLocation()` now compares normalized coordinates before and after every update. A real coordinate change resets all derived calculations, including GTS results, temperature windows, year curves, axis statistics, hint HTML, and the reverse-geocoded label. Weather and location-name caches remain available because their keys already include coordinates. Numerically equivalent wrapped longitudes do not trigger invalidation.

   Regression coverage: [locationStore.test.js](../tests/locationStore.test.js) verifies that moving a location clears derived data while retaining coordinate-keyed caches, and that an equivalent wrapped longitude preserves calculations. After the fix, the full suite passes normally and with `TZ=America/Los_Angeles` (20 suites, 84 tests); `npm run lint` passes.

5. **Confirmed defect — custom plant settings can be silently replaced.**
   If no stored entry has a nonempty URL, opening the dashboard replaces the entire dataset with defaults. This deletes legitimate custom entries without links, including an intentionally empty list. Malformed JSON is logged during migration but then parsed again without recovery, causing rendering to fail. Both cases were reproduced.
   References: [information.js](../assets/js/information.js), lines 374 and 409.

   **FIXED — 2026-10-01.** Missing storage now initializes the defaults, while every valid stored array—including an empty list or URL-free custom rows—is preserved. URL migration only adds a missing URL to a matching known default plant and does not replace the array. Malformed or non-array storage produces a safe empty runtime view without overwriting the stored value. The settings page also distinguishes an intentionally empty array from invalid data.

   Regression coverage: [information.test.js](../tests/information.test.js) verifies URL-free custom data, an intentionally empty list, malformed JSON recovery without overwrite, and URL migration for a known default plant. All four regressions failed before the fix. After the fix, the full suite passes normally and with `TZ=America/Los_Angeles` (20 suites, 89 tests); `npm run lint` passes.

6. **Confirmed defect — “Clear Cache” misses the current weather caches.**
   It removes top-level keys containing `historical` or `recent`, while current caches live inside `beelotLocations`.
   References: [einstellungen.html](../components/einstellungen.html), line 107; [locationStore.js](../assets/js/locationStore.js), line 291.

   **FIXED — 2026-10-01.** The settings action now clears the weather and location-name caches inside every stored location, as well as legacy top-level `historical_*` and `recent_*` entries. Location coordinates, calculated results, UI state, plant settings, and unrelated storage entries remain intact. Clearing the cache after clearing all local storage does not recreate location data.

   Regression coverage: [cacheClearing.test.js](../tests/cacheClearing.test.js) exercises the settings button with two locations and verifies current and legacy cache removal plus preservation of non-cache data. The full Jest suite passes normally and with `TZ=America/Los_Angeles` (22 suites, 91 tests); `npm run lint` passes.

7. **Confirmed defect — missing temperature values become apparently valid GTS values.**
   Response validation checks only `daily.time`. `Math.max(0, null)` converts missing temperatures to zero; missing arrays can throw. Forecast completion checks the last date, not whether temperatures are present, so trailing null values are not repaired.
   References: [dataService.js](../assets/js/dataService.js), line 48; [logic.js](../assets/js/logic.js), line 96; [plotUpdater.js](../assets/js/plotUpdater.js), line 395.

   **FIXED — 2026-10-01.** The weather-data boundary now requires matching date and temperature arrays. Shared merging retains only finite numeric temperatures, preserving measured zeroes while leaving missing values identifiable. GTS calculation skips missing values instead of coercing them to zero. Both the location and comparison paths now find the first missing date in the recent range and request replacement data, so a trailing null date no longer prevents forecast completion.

   Regression coverage: [dataService.test.js](../tests/dataService.test.js) verifies malformed response rejection, equal array lengths, and the distinction between zero and missing values; [logic.test.js](../tests/logic.test.js) verifies that missing values do not become GTS points; [plotUpdaterConcurrency.test.js](../tests/plotUpdaterConcurrency.test.js) verifies repair of a trailing missing historical temperature with recent data. The full Jest suite passes normally and with `TZ=America/Los_Angeles` (22 suites, 101 tests); `npm run lint` passes.

## WARNING

1. **Confirmed defect — release versions are determined before pulling branches.**
   The script reads local `dev`, computes the tag, then pulls and merges. Updated remote versions or a higher version on `main` can leave the tag inconsistent with released files. Existing tags are skipped without checking their target; remote lookup failures are treated as absence.
   References: [release_from_dev.py](../scripts/release_from_dev.py), lines 244 and 262.

   **FIXED — 2026-10-01.** The release version is now selected only after both `dev` and `main` have been pulled, using the highest value from both version files on both synchronized branches. Local and remote tags are resolved to commits and must match the release commit. Remote lookup failures abort the release, and a verified local tag is pushed when its remote counterpart is missing.

   Regression coverage: [test_release_from_dev.py](../scripts/tests/test_release_from_dev.py) contains eight isolated tests covering both-branch version selection, operation order, annotated remote tags, lookup failure, mismatched tags, verified existing tags, missing remote tags, and new tag creation. `python3 -m unittest discover -s scripts/tests -p 'test_*.py'`, Ruff, Black, the existing version-sync shell test, the full Jest suite (22 suites, 101 tests), and ESLint all pass.

2. **Confirmed defect — hotfix preparation modifies files before confirmation.**
   Version synchronization happens before the confirmation prompt. There is no clean-worktree check, and the subsequent commit includes any already-staged changes. An unconditional commit also fails when the version change was already committed.
   Reference: [release_current_hotfix.py](../scripts/release_current_hotfix.py), line 234.

3. **Confirmed destructive behavior — cleanup has an unrestricted working-directory scope.**
   It deletes matching backups recursively, flattens other backup files into one directory where duplicate basenames can overwrite each other, and prints success without reliable failure handling. There is no dry run, help, or repository-root check.
   Reference: [cleanup.sh](../scripts/cleanup.sh), line 12.

4. **Probable problem — retagging may do nothing while permitting broad force-pushes.**
   `git tag -f "$tag" "$tag"` points a tag back to its existing object; an unchanged push does not provide a reliable release trigger. If local and remote tags differ, the default `v*` operation can overwrite remote tags. The script does require confirmation.
   Reference: [retag_release_sync.sh](../scripts/retag_release_sync.sh), line 135.

5. **Probable problem — weather caches grow indefinitely and preserve provisional data.**
   Date-range responses have no expiry. Each update serializes the whole location store, including weather, calculated curves, and cached HTML. Quota errors only produce console warnings. Multiple browser tabs can overwrite each other’s independently loaded state.
   References: [dataService.js](../assets/js/dataService.js), lines 153 and 270; [locationStore.js](../assets/js/locationStore.js), line 184.

6. **Probable problem — asynchronous failures and partial results are inadequately surfaced.**
   Fragment fetches have neither HTTP-status checks nor rejection handlers. Historical-year failures are reduced to warnings and omitted curves. Comparison rendering checks its active state before awaiting, allowing a late comparison response to replace a location chart. Browser requests have no timeout or cancellation.
   References: [index.html](../index.html), line 55; [logic.js](../assets/js/logic.js), line 282; [main.js](../assets/js/main.js), line 1223.

7. **Confirmed defect — keyboard shortcuts interfere with editing and native controls.**
   Typing `+` or `-` in address/name fields also changes the date. Left/right arrows are intercepted on selects and radio buttons because those controls are excluded from the editable-control guard.
   Reference: [main.js](../assets/js/main.js), line 2139.

8. **Confirmed accessibility defects — several actions are unavailable through normal keyboard navigation.**
   Add/remove location buttons have `tabindex="-1"` and are excluded from arrow navigation. Settings headings and delete icons are clickable non-button elements. Dynamically created settings inputs lack individual accessible labels. Dialogs lack accessible-name associations, focus containment, and Escape handling.
   References: [main.js](../assets/js/main.js), line 1579; [locationTabNavigation.js](../assets/js/locationTabNavigation.js), line 25; [einstellungen.html](../components/einstellungen.html), line 36; [settings.js](../assets/js/settings.js), line 73; [index.html](../index.html), line 249.

9. **Confirmed CSS conflict; probable visual regression risk.**
   `index.css` loads after `style.css` and overrides some mobile rules with equally specific base rules, including location-panel spacing and plot-wrapper height. Fixed plot heights and overflow clipping warrant browser checks. The settings page also lacks a viewport meta tag.
   References: [index.html](../index.html), line 21; [style.css](../assets/css/style.css), line 129; [index.css](../assets/css/index.css), lines 84 and 431; [einstellungen.html](../components/einstellungen.html), line 3.

## INFO

**Intentional feature — leap-year curves retain their additional day. This is not an error.**

The original ERROR finding 3 is withdrawn following clarification of the intended design. Multi-year curves retain their natural daily sequence and are compared by day index without inserting gaps. Leap-year curves have an additional day after February 28. The shared x-axis displays the dates of the youngest (most recent) curve; it does not promise matching calendar dates for every older curve.

- If the youngest curve is 2026, its dates agree with the axis, as do those of 2025. The 2024 leap-year curve remains day-index correct but no longer matches the axis’s calendar dates after February 28.
- If the youngest curve is 2020, its leap-year dates agree with the axis. The 2019 curve remains day-index correct but no longer matches the axis’s calendar dates after February 28.

Preserve this behavior during future changes. Tests should verify the youngest curve’s date labels and the differing curve lengths, rather than require all years to align by calendar date. This design clarification does not change the separate findings about time-zone handling, DST arithmetic, or threshold-crossing calculations.

References: [charts.js](../assets/js/charts.js), lines 463 and 476; [faq.html](../components/faq.html), line 418.

## RECOMMENDED BEFORE FEATURE DEVELOPMENT

1. **Protect data integrity first:** add focused regression tests and fix request ownership, coordinate-cache invalidation, and destructive settings migration.
2. **Establish calendar correctness:** use consistent date-only handling and correct crossing-date comparisons. Preserve the intentional day-index comparison, additional leap-year day, and date axis based on the youngest curve.
3. **Harden weather/storage boundaries:** validate complete responses and stored shapes, distinguish missing temperatures from zero, and make cache clearing effective.
4. **Make releases predictable:** determine versions after synchronization, validate tags before mutations, protect staged changes, and synchronize lockfile metadata.
5. **Refresh dependencies narrowly:** address advisories, align supported lint/runtime versions, and pin the production chart dependency. Avoid an indiscriminate forced upgrade.
6. **Add a small CI baseline:** existing tests/lint, a second time zone, the portable script test, and targeted regression cases.
7. **Repair keyboard access and document setup.** Consolidate duplicated helpers only where needed for these fixes; no large architectural change is warranted.
